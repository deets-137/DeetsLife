# DeetsLife

An interactive 3D art project: a walkable, gamified space representing the music of my life,
organized by **eras**. Jukeboxes and records are the interaction hubs; photos and other media
get layered in over time. Ships as both an interactive build *and* a recorded cinematic walkthrough.

## Tech stack

- **Blender** — all 3D modeling, UV, texturing/baking. Native `.blend`; export to `.glb` (preferred) / `.fbx`.
- **Unity** — assembly, lighting, interaction, gamification, builds, and the recorded film
  (Cinemachine + Unity Recorder). Render pipeline: **URP**. Scripting: **C#**.
- **Lightroom** — photo processing and per-era color grading; export to `assets/lightroom-exports/`.
- **Python** — data tooling (`scripts/`), e.g. enriching the song list with artwork + 30s previews.

## Key technical constraints (don't violate without flagging)

- **Scale:** 1 Blender unit = 1 meter = 1 Unity unit. Lock this everywhere.
- **Materials don't fully cross Blender→Unity.** Bake to PBR maps (baseColor / metallic / roughness /
  normal / emissive) and rebuild simple materials in Unity. Final chrome/glass look is finalized in Unity.
- **Glow = emissive material**, animated in Unity to react to audio.
- **Audio:** use Apple/iTunes 30-second preview URLs (free, no auth) for in-world playback. Never bundle
  full tracks. The data model carries a `previewUrl` per song.
- **Version control:** Git + **Git LFS** from day one (see `.gitattributes`). 3D/photo/audio assets are
  binary and large — never commit them as plain git objects.
- The Unity project and Blender working files live under this repo but are gitignored where appropriate
  (Unity `Library/`, `Temp/`, etc.). C# scripts are tracked.

## Working principle: vertical slice first

Do NOT scale before the full loop works once. Target the first milestone:
**one era → one room → one jukebox → ~5 records → one photo on the wall → walk up → click record →
hear the 30s preview → see the photo.** Only after that loop runs do we add eras, records, viz, and film.

## Conventions

- C# scripts target Unity's MonoBehaviour conventions; data classes are `[Serializable]`.
- Unity `JsonUtility` can't parse a top-level JSON array, so the canonical data file is an OBJECT
  with `eras` and `songs` arrays (see `data/library.sample.json`).
- Keep the data model the single source of truth shared by the Python tooling and the C# loader.
